# Web console screenshots

12 PNG screenshots of the MeshSync web console (v1.0.0), all captured from the
running application during the live two-agent demo described in the root
`README.md`: `mesh-alpha` (127.0.0.1:3040/4040) and `mesh-beta`
(127.0.0.1:3041/4041) as trusted peers with a shared `Documents` folder and a
real transfer/conflict/event history. Nothing is mocked: every value visible
in the shots — peer IDs, SHA-256 fingerprints, byte counts, progress, errors —
comes from the actual agents and the C++ native hashing worker
(`cpp-worker-1.0.0`, agent v0.1.0 at capture time).

Capture context: console served through the Caddy gateway at
`http://localhost:81/` (gateway → Next.js console → agent APIs), desktop
viewport 1440×900 except `10-mobile-fa-rtl.png` at 390×844.

| File | What it shows |
| --- | --- |
| `01-device-en-light.png` | Device workspace, English, light theme — live stats from mesh-alpha including the active C++ native engine (`cpp-worker-1.0.0`), identity, ports (3040/4040) and folder/file/peer counters. |
| `02-peers-fa-rtl.png` | Peers workspace, Persian, RTL layout — trusted peer mesh-beta (peer ID `ec365de7ff166c54`, agent v0.1.0) with the two-node mesh view and peer detail card. |
| `03-folders-en-light.png` | Folders workspace, English, light theme — the shared Documents folder as indexed at capture time (7 files, 320 MiB) with its sync state against mesh-beta. |
| `04-files-en-light.png` | Files workspace, English, light theme — Documents file browser listing the synced files (readme.txt, notes.txt, quarterly-report.txt, demo-from-web.txt, big-dataset.bin at 64 MiB and 100% synced). |
| `05-sync-plan-en.png` | Sync workspace, English, light theme — a computed sync plan for Documents with PUSH actions against mesh-beta (e.g. archive-2026.tar, 256 MiB) before execution. |

Notes:

- `06-transfer-active-en.png` was captured mid-sync with two transfers running
  simultaneously; the progress and throughput numbers are real measurements
  from the transfer manager, not staged values.
- `12-error-recovery-en.png` is the failure-path demo: an agent was stopped on
  purpose, the console surfaced the unreachable/reconnecting state, and it
  returned to the live stream once the agent self-healed (agents are
  supervised and restarted by the console's agent supervisor).
- The console was always accessed through the Caddy gateway on port 81;
  direct access to the Next.js dev server on :3000 does not route agent API
  calls and is not representative.

All shots are PNG; the 11 desktop shots are 1440×900 and the mobile shot is
390×844. Screenshots are checked in as documentation assets and are not
regenerated by CI.
