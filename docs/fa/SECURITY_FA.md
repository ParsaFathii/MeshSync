# امنیت MeshSync

این سند فقط چیزهایی را می‌گوید که واقعاً در کد پیاده شده است. هر ادعا به
`agent/` برمی‌گردد. نسخهٔ انگلیسی با جزئیات کامل‌تر:
[SECURITY.md](../../SECURITY.md).

## هویت و اعتماد

- هویت هر دستگاه یک جفت‌کلید **Ed25519** ماندگار است
  (`~/.meshsync/identity.key`، مجوز `0600`). شناسهٔ همتا از هش کلید
  عمومی می‌آید (۸ بایت اول SHA-256، hex) و اثر انگشت قابل کنترل انسانی
  در `GET /device` هست.
- وضعیت‌ها: `DISCOVERED` → `PAIRING` → `TRUSTED` و `REVOKED`. فقط همتای
  `TRUSTED` می‌تواند مانیفست، قطعه یا حذف ردوبدل کند؛ سرور این را بعد
  از handshake برای هر پیام غیر از جفت‌سازی چک می‌کند.
- **کشف هرگز اعتماد نمی‌سازد**؛ بیکِن UDP فقط ثبت می‌کند و اعتماد با
  `approve` صریح سمت مقابل ساخته می‌شود.
- **Pin کردن کلید:** بعد از جفت‌سازی، کلید عمومی همتا در دیتابیس ذخیره
  می‌شود؛ در هر اتصال بعدی، کلید گواهی باید با همان بخواند، وگرنه
  اتصال با خطای `IDENTITY_MISMATCH` بسته می‌شود. دستگاهی که هویتش را
  از نو ساخته باید حذف و دوباره جفت شود.
- **لغو:** `POST /peers/{id}/revoke` همتا را `REVOKED` می‌کند؛
  handshakeهای بعدیاش با خطای `REVOKED` رد و جفت‌سازی مجددش reject
  می‌شود تا رکورد با `DELETE /peers/{id}` حذف شود. توجه: لغو، سمت شما
  اعمال می‌شود؛ دستگاه مقابل کپی فایل‌های قبلی را همچنان دارد.

## امنیت انتقال (`netproto/tls.go`)

- اتصال همتاها **TLS 1.3** روی TCP است با گواهی self-signed که کلیدش
  همان کلید هویت دستگاه است؛ خودامضایی گواهی هم verify می‌شود. گواهی
  CA-دار یا با کلید خارجی، handshake را fail می‌کند.
- سمت کلاینت، کلید مورد انتظار داخل `VerifyPeerCertificate` pin می‌شود؛
  مغایرت کلید، handshake را قطع می‌کند («peer key does not match pinned
  identity»). تنها استثنا dial اولیهٔ جفت‌سازی است که کلید عمداً ناشناخته
  است تا یاد گرفته و برای تأیید به کاربر نشان داده شود.
- HELLO باید شناسهٔ گواهی را تکرار کند؛ مغایرت = `IDENTITY_MISMATCH`.
- سقف فریم ۱۷ MiB (۱۶ MiB قطعه + جای هدر) و طول‌های نامعتبر قبل از هر
  تخصیص رد می‌شوند.
- تایم‌اوت‌ها: handshake سمت سرور ۱۵ ثانیه، dial کلاینت ۱۰ ثانیه،
  timeout خواندنِ idle ۹۰ ثانیه — هزینهٔ اتصال‌های کند/خراب را محدود
  می‌کنند.

## امنیت API (`api/api.go`)

- **پیش‌فرض localhost:** API روی `127.0.0.1:3040` گوش می‌دهد؛ تغییر با
  `--api-bind` / `MESHSYNC_API_BIND` یک انتخاب صریح است. اگر به LAN
  بازش کردید، حتماً توکن بگذارید.
- **توکن اختیاری:** با `--api-token` / `MESHSYNC_API_TOKEN`، همهٔ
  درخواست‌ها (از جمله ارتقای WebSocket) باید
  `Authorization: Bearer <token>` داشته باشند؛ وگرنه `401 UNAUTHORIZED`.
- **Rate limit:** ۶۰۰ درخواست در ۱۰ ثانیه به‌ازای هر IP؛ بیش از آن
  `429 RATE_LIMITED`. برای داشبورد کافی است و حلقه‌های حسابی را مهار
  می‌کند.
- **محدودیت ورودی:** بدنه‌های JSON تا ۱ MiB؛ `ReadHeaderTimeout` ده
  ثانیه؛ درخواست‌های قطعه از نظر طول/آفست/تطابق داده با هدر اعتبارسنجی
  می‌شوند.
- **اعتبارسنجی:** آدرس جفت‌سازی باید `host:port` باشد؛ مسیر پوشه باید
  دایرکتوری مطلق موجود باشد؛ تنظیمات range-check می‌شوند (اندازهٔ قطعه
  ۶۴ KiB–۱۶ MiB، همزمانی ۱–۸ و …)؛ اجرای sync به همتای `TRUSTED` و
  در دسترس نیاز دارد.
- **CORS:** `Access-Control-Allow-Origin: *` و upgraderِ WS هر origin ای
  را می‌پذیرد. در استقرار محلیِ localhost مشکلی نمی‌سازد و همین است که
  اجازه می‌دهد کنسول وب (که از پورت/origin دیگری سرو می‌شود) ایجنت را
  هدایت کند. **اگر API را به کارت شبکهٔ LAN بایند کردید، حتماً توکن
  ست کنید** — وگرنه هر صفحهٔ وبی که در مرورگر روی همان LAN باز کنید
  می‌تواند به API بدون احراز برسد.

## محافظت‌های فایل‌سیستم

- **اعتبارسنجی مسیر (`SafeJoin`):** هر مسیرِ ریموت — درخواست قطعه، حذف،
  حل تعارض — داخل ریشهٔ پوشهٔ اشتراکی resolve می‌شود و در صورت مسیر
  مطلق، سگمنت `..` (هم بررسی سگمنت‌به‌سگمنت هم resolution واژگانی)،
  بک‌اسلش، NUL یا خروج از ریشه، رد می‌شود.
- **سیاست symlink:** فقط فایل‌های regular نمایه، منتقل و دریافت
  می‌شوند؛ symlink، سوکت و فایل دستگاهی هیچ‌وقت sync نمی‌شوند؛ پس
  symlink نمی‌تواند نوشتن را بیرون از پوشه هدایت کند.
- **حذف ایمن:** `DELETE_FILE` ریموت فقط وقتی اجرا می‌شود که محتوای فعلی
  ما هنوز به `expectedHash` بخورد؛ وگرنه حذف رد و مسیر تعارض می‌شود.
- **صحت‌سنجی:** هر قطعه SHA-256 می‌شود، فایل اسمبل‌شده کامل re-hash
  می‌شود، و rename نهایی اتمیک است؛ فایل part خراب پاک می‌شود تا retry
  تمیز شروع شود.
- **سطل زباله:** حذف‌ها و بازنویسی تعارض، نسخهٔ بازنده را اول به
  `~/.meshsync/trash/<folder>/` می‌برند.
- فایل‌های part در `~/.meshsync/parts/` بیرون از پوشه‌های اشتراکی
  می‌نشینند؛ دادهٔ ناقص هرگز در مسیر مقصد دیده نمی‌شود.

## تهدیدها و پاسخ‌ها

| تهدید | پاسخ در کد |
|---|---|
| MITM روی اتصال همتا | TLS 1.3؛ کلید گواهی = هویت Ed25519 pinشده؛ verify خودامضایی؛ مغایرت کلید = قطع handshake |
| همتای غیرمجاز روی LAN | تأیید صریح جفت‌سازی؛ ترافیک sync فقط با `TRUSTED`؛ `REVOKED` در handshake رد می‌شود |
| جعل هویت (استفادهٔ مجدد peerId) | شناسه از کلید عمومی pinشده مشتق می‌شود؛ HELLO باید با گواهی بخواند؛ کلید عوض‌شده = `IDENTITY_MISMATCH` |
| دستکاری فایل در مسیر انتقال | هش هر قطعه + verify کامل قبل از rename؛ خرابی، part را دور می‌ریزد |
| دستکاری فایل روی دیسک | هش‌ها در scan دوباره محاسبه می‌شوند؛ فایلِ ناهمخوان با برنامه، انتقالش fail می‌شود |
| replay پیام‌های قدیمی | حفاظت record در TLS 1.3؛ حذف‌ها به هش محتوای مورد انتظار گره خورده‌اند؛ انتقال‌ها به هش برنامه لنگرند |
| فریم‌های خراب/دشمنانه | سقف ۱۷ MiB؛ decodeهای سخت‌گیرانه؛ تایم‌اوت‌های handshake/خواندن؛ سقف بدنه؛ rate limit |
| پیمایش مسیر / فرار symlink | `SafeJoin` روی همهٔ مسیرهای ریموت؛ فقط regular files؛ نوشتن محدود به ریشهٔ پوشه‌ها و state dir |
| کلاینت محلیِ حساب‌شده | ۶۰۰ req/10s → `429`؛ رویدادهای throttleشده؛ مشترک کندِ WS فریم drop می‌کند نه اینکه ایجنت را بلاک کند |

## پیش‌فرض‌های امن

- bind API روی `127.0.0.1`؛ فقط با پرچم/env عوض می‌شود.
- بدون توکن (فرض تک‌کاربرهٔ محلی) — قبل از هر bind غیرlocalhost توکن
  اضافه کنید.
- کشف روشن ولی فقط ثبت؛ اعتماد هرگز خودکار نیست.
- پهنای باند نامحدود (۰)، همزمانی ۲، قطعهٔ ۱ MiB، همگام‌سازی فقط دستی.

## چه چیزهایی پوشش داده نمی‌شود

- **فقط LAN.** بدون رله، بدون NAT traversal، بدون زیرساخت PKI/CT؛
  امنیت TLS روی pin کردن کلید تکیه دارد نه web-of-trust عمومی.
- **رمزنگاری در حالت سکون وجود ندارد.** فایل‌ها، SQLite و سطل زباله
  روی هر دستگاه plaintext هستند؛ اگر لازم است، از رمزنگاری دیسک
  استفاده کنید.
- **مدل تک‌کاربره.** هرکس به API محلی (یا یک همتای مورد اعتماد) دسترسی
  داشته باشد، به همهٔ چیزهای اشتراکی دسترسی کامل دارد؛ نه حساب کاربر
  هست، نه ACL، نه امضای حسابرسی.
- مقایسهٔ توکن string ساده است و توکن در هدر هر درخواست می‌رود؛ مثل
  رمز عبور با آن رفتار کنید. اگر لو رفت، عوضش کنید.
- **همتای revoke شده داده‌اش را نگه می‌دارد.** لغو، تبادل آینده را قطع
  می‌کند؛ نمی‌تواند از راه دور چیزی را روی دستگاه مقابل حذف یا قفل کند.
- در برابر «دستگاه مورد اعتمادِ نفوذشده» محافظتی نیست — اعتماد در
  MeshSync یعنی خواندن/نوشتن کامل پوشه‌های مشترک، به‌طور عمدی.
