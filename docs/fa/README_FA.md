# MeshSync — همگام‌سازی فایل به‌صورت همتا-به-همتا و محلی-اول

MeshSync پوشه‌ها را بین دستگاه‌های خودتان روی شبکهٔ محلی همگام می‌کند؛
بدون سرویس ابری، بدون واسطه، مستقیم بین دو دستگاه. هر دستگاه یک ایجنت
سبک اجرا می‌کند که مالک همهٔ وضعیت خودش است: یک دیتابیس SQLite محلی،
هش محتوای فایل‌ها، اتصال مستقیم به دستگاه‌های دیگر و یک API نسخه‌دارِ
REST + WebSocket روی `127.0.0.1`. کنسول وب و کلاینت Flutter فقط مصرف‌کنندهٔ
همان API هستند؛ هیچ منطق همگام‌سازی‌ای سمت کلاینت وجود ندارد.

## MeshSync برای چیست؟

- یک پوشهٔ کاری که روی دسکتاپ و لپ‌تاپِ روی یک شبکهٔ محلی باید یکسان
  بماند، بدون اینکه هیچ شخص ثالثی بایت‌ها را ببیند.
- جابه‌جا کردن فایل‌های حجیم (ویدیو، دیسک VM، دیتاست) بین دو ماشین،
  بدون آپلود و بدون دیسک خارجی.
- ادامهٔ کار در حالت آفلاین: هر دستگاه یک کپی کامل از پوشه دارد؛
  همگام‌سازی یک تصمیم محلی است، نه دروازه‌ای که باید از آن رد شوید.
- دیدن تغییرات قبل از اجرای آن‌ها: برنامه‌ریز همگام‌سازی قبل از هر
  جابه‌جایی، دسته‌بندی کامل مسیرها را تولید می‌کند.

مواردی که MeshSync برایشان ساخته نشده: دستگاه‌هایی که هیچ‌وقت به هم
می‌رسند (MeshSync فقط شبکهٔ محلی است؛ رله و عبور از NAT وجود ندارد) و
اشتراک‌گذاری چندکاربره با سطح دسترسی per-file (مدل اعتماد، per-device و
تک‌کاربره است).

## مدل کلی سیستم

```
 Flutter client ──┐                         ┌── Flutter client
 Web console   ───┤ HTTP + WS :3040         ├─ HTTP + WS :3041
 curl/scripts  ───┘          │              ┘
                    meshsync-agent (Go)     meshsync-agent (Go)
                    SQLite · file index ·   SQLite · file index ·
                    C++ hashing worker      C++ hashing worker
                             │                       │
                             └── TLS 1.3 peer TCP ───┘
                                              TCP 4040 ↔ 4041
             UDP multicast discovery 239.255.42.42:4100
```

(کلاینت‌ها فقط با ایجنت محلی خودشان حرف می‌زنند؛ ایجنت‌ها مستقیم با هم.)

## خلاصهٔ رفتارها

- **کشف همتا** با بیکِن UDP مالتی‌کست روی `239.255.42.42:4100` (هر ۵
  ثانیه). همتای دیده‌شده فقط «ثبت» می‌شود؛ هرگز خودکار مورد اعتماد
  نمی‌شود. جزئیات: [PEERS_FA.md](PEERS_FA.md).
- **اعتماد** چهار وضعیت دارد: `DISCOVERED`، `PAIRING`، `TRUSTED` و
  `REVOKED`. جفت‌سازی دوطرفه و صریح است و کلید Ed25519 طرف مقابل بعد از
  اولین TLS pin می‌شود. جزئیات: [PEERS_FA.md](PEERS_FA.md) و
  [SECURITY_FA.md](SECURITY_FA.md).
- **همگام‌سازی برنامه‌اول (plan-first)**: قبل از هر جابه‌جایی، مانیفست
  دو طرف ردوبدل و همهٔ مسیرها در یکی از هشت وضعیت `UNCHANGED` /
  `LOCAL_ONLY` / `REMOTE_ONLY` / `LOCAL_MODIFIED` / `REMOTE_MODIFIED` /
  `CONFLICT` / `DELETE_LOCAL` / `DELETE_REMOTE` دسته‌بندی می‌شوند.
  مقایسه‌ها فقط با هش SHA-256 محتوا انجام می‌شود، نه زمان تغییر فایل.
  جزئیات: [SYNC_FA.md](SYNC_FA.md).
- **انتقال قطعه‌ای و ازسرگیری‌پذیر**: قطعه‌های ۱ MiB (پیش‌فرض؛ بازهٔ
  ۶۴ KiB تا ۱۶ MiB)، هش SHA-256 برای هر قطعه و برای کل فایل، فایل part
  خارج از پوشهٔ اشتراکی، و رنم اتمیک در پایان. نگاشت قطعه‌ها در SQLite
  ذخیره می‌شود؛ pause/resume/cancel/retry حتی بعد از ری‌استارت ایجنت
  کار می‌کنند.
- **تعارض**: وقتی هر دو طرف یک مسیر را از آخرین نسخهٔ مشترک تغییر
  داده‌اند، هیچ‌چیز بازنویسی نمی‌شود؛ تعارض ثبت می‌شود و با
  `KEEP_LOCAL` / `KEEP_REMOTE` / `KEEP_BOTH` / `LATER` حل می‌شود. نام
  فایل نسخهٔ دوم در `KEEP_BOTH` قطعی است:
  `report (conflict from mesh-beta 2026-10-08).pdf`. جزئیات:
  [CONFLICTS_FA.md](CONFLICTS_FA.md).
- **پیش از هر عمل مخرب، سطل زباله**: حذف محلی، حذف از راه دور و
  بازنویسی ناشی از تعارض، نسخهٔ بازنده را اول به
  `~/.meshsync/trash/<folder>/` می‌برند.
- **ایمنی**: API به‌صورت پیش‌فرض روی `127.0.0.1` گوش می‌دهد؛ توکن
  اختیاری؛ محدودسازی نرخ؛ اعتبارسنجی سخت‌گیرانهٔ مسیرها. جزئیات:
  [SECURITY_FA.md](SECURITY_FA.md).
