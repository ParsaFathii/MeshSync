# راهنمای توسعه

معادل فارسیِ [CONTRIBUTING.md](../../CONTRIBUTING.md). قراردادِ منجمدِ
[docs/API.md](../API.md) تنها مرجع رفتار است: ایجنت، وب و Flutter هر سه
همان یک سند را پیاده می‌کنند. اگر رفتاری باید عوض شود، اول قرارداد را
(به‌عنوان پیشنهاد) تغییر دهید، بعد کد را.

## محیط توسعه

- **ایجنت Go:** Go 1.25+ (مطابق `agent/go.mod`)، بدون cgo — SQLite از
  `modernc.org/sqlite` است و `go build` بدون دردسر کار می‌کند.
- **موتور بومی:** g++ با پشتیبانی C++20 در `native/cpp` (ساخت با `make`).
- **کنسول وب:** Bun یا Node نسخهٔ ۱۸+ (`bun install` در ریشهٔ مخزن).
- **کلاینت Flutter:** Flutter SDK سری ۳.

## ساخت و تست

```sh
# ایجنت
cd agent && go build ./... && go test ./...

# موتور هش بومی
cd native/cpp && make && make test

# کنسول وب
bun install
bun run dev        # http://localhost:3000
bun run lint

# کلاینت Flutter
cd flutter
flutter pub get
flutter analyze
flutter test
```

## چیدمان مخزن

```
agent/           ایجنت Go (cmd/meshsync-agent + internal/*)
native/cpp/      موتور هش C++20 + تست‌ها
flutter/         کلاینت Flutter (اندروید و لینوکس)
src/             کنسول وب (Next.js، TypeScript، Tailwind، shadcn/ui)
docs/            API.md، QUICKSTART.md، assets/ (نمودارهای SVG)، fa/ (فارسی)
prisma/, db/     ذخیره‌سازی رجیستری endpointها برای کنسول وب
.github/         workflowهای CI و قالب issue
deploy/          بسته‌بندی Docker
scripts/         اسکریپت‌های انتشار و ابزارها
```

مرز کامپوننت‌ها سخت است: کلاینت‌ها فقط API ایجنت را مصرف می‌کنند؛ ایجنت
هرگز کد کلاینت را import نمی‌کند؛ موتور بومی یک پروسهٔ جداگانه است که
پروتکل JSON-lines مستندش را حرف می‌زند. همین جداسازی است که ساخت و تست
هر قطعه را مستقل نگه می‌دارد — آن را خراب نکنید.

## تست دو‌ایجنتی دستی

```sh
./meshsync-agent --name alpha --api-port 3040 --peer-port 4040 --data-dir ~/.meshsync-a
./meshsync-agent --name beta  --api-port 3041 --peer-port 4041 --data-dir ~/.meshsync-b
```

جفت‌سازی کنید، در دو طرف پوشه‌ای با یک نام بسازید و همگام‌سازی را با
curl یا کنسول جلو ببرید (مراحل در [USER_GUIDE_FA.md](USER_GUIDE_FA.md)).

## سبک کامیت

- پیشوند scoped به کامپوننت: `agent:`، `native:`، `web:`، `flutter:`،
  `docs:`، `ci:`، `chore:`.
- عنوان در وجه امر و حدوداً زیر ۷۲ نویسه، بدون نقطه در انتها.
  نمونهٔ خوب: `agent: skip re-hash when size+mtime unchanged in rescan`.
- اگر «چرا» از خودِ diff معلوم نیست، در بدنه توضیح بدهید. هرجا رفتار به
  قرارداد API ربط دارد، به بخش مربوط در API.md ارجاع بدهید.
- یک تغییر منطقی در هر کامیت؛ فایل‌های تولیدی و نویز فرمت همراه کامیتِ
  فیچر نمی‌آیند.

## انتظارات Pull Request

- تست و lint کامپوننتِ مربوط به‌صورت محلی سبز باشد.
- اگر رفتار ایجنت عوض شده: e2e دو‌ایجنتی پاس بماند و هر endpoint/فیلد
  جدید در `docs/API.md` (و معادل فارسی اگر برای کاربر دیده می‌شود) هم
  بیاید.
- اگر پروتکل سیمی تغییر کرده: سازگاری با نسخه‌های قبلی توضیح داده شود
  (نسخه‌ها در HELLO ردوبدل می‌شوند).
- رشته‌های جدیدِ کنسول/Flutter با هر دو مقدار `en` و `fa` بیایند.
- بدون secret و توکن و مسیر مطلقِ ماشین خودتان در diff.

## چک‌لیست بازبینی کد

این فهرست همان کلاس‌های باگی است که این کدبهی بیش از همه در معرضشان
است — نویسنده قبل از PR و بازبین بعد از آن بررسی کنند:

- [ ] **Race:** نقشه‌ها/اسلایس‌های اشتراکی محافظت‌شده باشند
      (`peersMu`، `Manager.mu`، `Bandwidth.mu`، `cfgMu`)؛
      `go test -race ./...` پاک باشد.
- [ ] **نشت گوروتین:** هر `go func` شرط خروج دارد؛ listenerها، tickerها
      و حلقه‌های watcher موقع shutdown می‌ایستند؛ جایی که `wg.Add`
      شده `defer wg.Done()` هست.
- [ ] **خطاهای چک‌نشده:** خطاهای فایل‌سیستم و DB یا event می‌شوند یا
      خطای API؛ `_ =` فقط برای «بهترین تلاش» با کامنت توضیحی.
- [ ] **عملیات خطرناک fs:** همهٔ نوشتن‌ها از `SafeJoin` رد شوند؛ هیچ
      `os.Remove` بدون سطل‌زباله برای محتوای اشتراکی نیست؛ در مسیر
      نهایی فایل ناقص نمی‌نشیند (اول parts/ بعد rename).
- [ ] **هش قبل از نابودی:** حذف و بازنویسی، هش مورد انتظار را چک
      می‌کنند؛ دادهٔ منحرف‌شده تعارض بشود، نه قربانی.
- [ ] **سلامت فریم/JSON:** پیام‌های جدیدِ سیمی سقف ۱۷ MiB را رعایت
      کنند؛ خطای decode اتصال را ببندد نه اینکه معلق بماند.
- [ ] **فراخوانی بلاک‌کننده:** هندلرها حلقهٔ خواندن را بلاک نکنند؛
      کار طولانی به گوروتین‌های manager/نشست سپرده شود.
- [ ] **اعتبارسنجی config:** تنظیمات جدید در `config.Validate` چک و در
      `ApplyConfig` به‌صورت زنده اعمال شوند.
- [ ] **مستندات:** تغییر رفتار در API.md / README / docs/fa هم بیاید.

مستندات هم کدند: پرچم، endpoint، پیش‌فرض یا رفتار سیمی که عوض می‌شود،
در همان PR باید در سند انگلیسی و فارسیِ مربوط به‌روز شود. نمودارهای
`docs/assets/` SVGهای دست‌سازند — به‌عنوان سورس ویرایششان کنید، با
خروجی رستر جایگزین نکنید.
